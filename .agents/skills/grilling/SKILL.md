# Grilling

사용자의 의도에서 중요한 빈칸을 임의로 채우지 않고, 합의된 요구사항을 바탕으로 구현을 시작하도록 돕는다. [프로젝트 작업 지침](../../../AGENTS.md)과 [작업 가이드](../../../docs/work-guide.md)의 현재 승인 범위를 따른다.

## 적용 조건

- 사용자가 계획·설계·결정을 인터뷰하거나 반박·검토해 달라고 명시적으로 요청할 때 사용한다.
- 업무 규칙, 데이터 의미, 저장·삭제 범위, 외부 동작, 완료 조건의 미결정이 구현 결과를 크게 바꿀 때 사용한다.
- 스킬 자체의 평가·설치 요청이나 요구가 분명한 작은 수정에는 인터뷰를 시작하지 않는다. 코드로 확인할 사실을 사용자 결정 문제로 바꾸지 않는다.

## 진행 방법

1. 현재 요청, 앞서 확정된 결정, 관련 문서·코드를 먼저 확인한다. 직접 조사할 수 있는 사실을 사용자에게 다시 설명하도록 요구하지 않는다. 사실이 확인되지 않았으면 미확인으로 표시한다.
2. 확인된 사실, 사용자가 확정한 요구, 제안·가정, 미결정 사항을 구분한다. 결정 사이의 의존 관계를 살펴 선행 조건이 정해진 질문부터 묻는다. 아직 답을 받지 않은 질문의 결과를 가정해 후속 선택을 확정하지 않는다.
3. 한 번에 답하기 쉬운 핵심 질문 1~3개를 사용 가능한 질문 도구로 제시한다. 여러 질문을 묶을 때는 서로 독립적으로 답할 수 있어야 한다. 구체적인 선택지의 차이·트레이드오프와 추천 근거를 제공하고, 추천이 달라지는 조건도 밝힌다. 단순 동의가 추천안을 채택하도록 유도하는 문구는 피한다.
4. 답변에 따라 이해와 남은 질문을 갱신한다. 무응답이나 시간 경과를 승인으로 해석하지 않는다. 사용자가 모르는 사항은 조사하거나 미결정으로 남기며, 그 답에 의존하지 않는 조사·작업은 계속할 수 있다.
5. 중요한 결정을 정리한 뒤 목표, 제외 범위, 기대 동작, 지켜야 할 데이터·API 계약, 완료·검증 조건을 필요한 만큼 요약한다. 사용자와 이해가 일치했는지 확인한 뒤 그 결정에 의존하는 구현을 진행한다. 이미 합의한 내용을 반복해서 승인받지 않는다.

## 종료와 기록

- 현재 승인된 범위의 구현에 필요한 중요한 결정이 정리되면 끝낸다. 가능한 미래 변경의 모든 분기를 소진할 때까지 질문하지 않는다.
- 확정된 요구와 남은 가정은 해당 작업의 기존 대표 문서·작업 기록에 구분해 남긴다. 별도 인터뷰 파일을 매 답변마다 자동 생성할 필요는 없다.
- 사용자 답변으로 사실관계까지 검증됐다고 간주하지 않는다. 실제 동작과 기술 정보는 코드·공식 자료·검사로 확인한다.
