# 제 1 장 서론

## 제 1 절 프로젝트 필요성 및 배경

청년을 대상으로 하는 복지 정책과 지원 사업은 중앙정부, 지방자치단체, 공공기관 등 다양한 주체에 의해 지속적으로 제공되고 있다. 정책 분야도 주거, 일자리, 교육, 금융, 생활 지원, 문화 활동 등으로 다양하며, 청년층의 생활 안정과 사회 진입을 지원하기 위한 정책의 중요성은 점차 커지고 있다.

그러나 실제 사용자인 청년의 입장에서는 자신에게 해당되는 정책을 한눈에 파악하기 어렵다. 정책 정보가 여러 기관과 플랫폼에 분산되어 있고, 정책마다 제공 기관, 신청 자격, 거주 지역, 소득 기준, 신청 기간, 제출 서류가 다르기 때문이다. 사용자는 여러 웹사이트와 공고문을 직접 확인해야 하며, 행정 문서 형식의 공고문에서 핵심 조건을 빠르게 이해해야 하는 부담도 크다.

이러한 구조에서는 실제로 수혜 대상에 해당하는 청년이라도 정보를 제때 확인하지 못해 신청 기회를 놓칠 수 있다. 특히 신청 기간이 짧거나 지역별로 제한된 정책은 사용자가 지속적으로 여러 기관의 공고를 확인하지 않으면 발견하기 어렵다. 이는 단순한 정보 제공의 문제가 아니라, 정책 정보와 개인 조건을 연결해 주는 체계가 부족하다는 문제로 볼 수 있다.

따라서 청년 복지 정책을 하나의 플랫폼에서 통합적으로 탐색할 수 있도록 하고, 사용자의 연령, 거주지, 소득 수준, 취업 상태, 관심 분야, 우선순위 등 개인 조건을 바탕으로 적합한 정책을 선별해 제공하는 서비스가 필요하다. 명확한 자격 조건은 규칙 기반으로 처리하고, 정책 내용과 사용자 상황의 적합성은 AI를 활용해 보조적으로 분석하는 방식은 정책 탐색의 효율성과 추천의 개인화 수준을 함께 높일 수 있다.

본 프로젝트는 이러한 문제를 해결하기 위해 AI 기반 개인 맞춤형 청년 복지 통합 플랫폼을 구현하였다. 본 플랫폼은 여러 출처의 청년 복지 정책 정보를 통합하여 검색과 상세 조회가 가능하도록 제공하고, 사용자 프로필을 기반으로 개인에게 적합한 정책을 추천한다. 또한 추천 사유, 챗봇 상담, 북마크, 알림, 관리자 데이터 품질 관리 기능을 함께 제공하여 정책 탐색부터 신청 준비까지 이어지는 통합적인 사용자 경험을 제공하고자 하였다.

## 제 2 절 관련 기술 및 선행연구

### 1. 공공데이터 통합 및 정책 데이터 정규화

공공 복지 정책 데이터는 제공 기관과 API에 따라 데이터 구조, 명칭, 분류 체계가 다르게 제공된다. 온통청년 API는 청년 정책 중심의 정책명, 정책 키워드, 정책 분류, 신청 기간 정보를 제공하고, 복지로 API는 중앙부처 및 지자체 복지서비스의 지원대상, 선정기준, 신청방법 정보를 제공한다. Gov24 공공서비스 API는 다양한 정부 혜택의 목록, 상세 정보, 지원조건을 제공한다[1][2][3][4][5].

이러한 데이터를 하나의 서비스에서 활용하기 위해서는 출처별 응답 구조를 내부 정책 모델로 변환하고, 지역, 분야, 대상, 신청 상태 등을 동일한 기준으로 정리하는 과정이 필요하다. 본 프로젝트에서는 수집한 정책 데이터를 내부 정책 테이블, 상세 정보 테이블, 지역 정보, 태그, 지원조건 fact로 분리하여 저장하였다. 이를 통해 출처가 다른 정책이라도 사용자는 동일한 검색 필터와 상세 화면에서 확인할 수 있으며, 추천과 챗봇 기능도 같은 정책 데이터 기반으로 동작할 수 있도록 설계하였다.

### 2. 개인화 추천 시스템과 하이브리드 추천 방식

개인화 추천 시스템은 많은 정보 중 사용자에게 적합한 항목을 우선적으로 제시하는 기술이다. 일반적인 콘텐츠나 상품 추천과 달리 복지 정책 추천은 사용자의 선호뿐만 아니라 연령, 거주 지역, 소득 수준, 취업 상태, 가구 형태와 같은 자격 조건이 중요하게 작용한다. 따라서 단순한 인기순 또는 키워드 유사도만으로는 사용자가 실제로 신청 가능한 정책을 효과적으로 찾기 어렵다.

하이브리드 추천 시스템 연구는 여러 추천 방식을 결합하여 단일 방식의 한계를 보완할 수 있음을 제시한다[8]. 본 프로젝트는 이러한 관점을 청년 복지 정책 추천에 적용하여, 명확한 조건은 룰 기반으로 먼저 반영하고, 정책 내용과 사용자 상황의 정성적 적합성은 OpenAI API를 활용한 보조 평가와 추천 사유 생성으로 보완하였다. 이를 통해 추천 결과의 계산 가능성과 설명 가능성을 함께 확보하고자 하였다.

### 3. 설명 가능한 추천

복지 정책 추천에서는 단순히 정책 목록을 제시하는 것만으로 충분하지 않다. 사용자는 해당 정책이 자신에게 왜 추천되었는지, 어떤 조건이 자신의 상황과 연결되는지 이해해야 실제 신청 여부를 판단할 수 있다. 설명 가능한 추천 연구는 추천 결과와 함께 이유를 제공함으로써 추천 시스템의 투명성, 신뢰성, 사용자 이해도를 높일 수 있음을 강조한다[9].

본 프로젝트에서는 추천 결과에 최종 점수뿐만 아니라 추천 사유를 함께 제공하도록 구현하였다. 추천 사유는 정책명만 나열하는 방식이 아니라 사용자의 지역, 관심 분야, 소득 구간, 취업 상태 등 범주형 조건과 정책의 지원 내용이 어떻게 연결되는지를 설명하는 데 초점을 두었다.

### 4. RAG 및 LLM 기반 정책 상담

LLM은 긴 문서를 요약하고 자연어 질의응답을 제공하는 데 강점을 가진다. 그러나 복지 정책과 같이 사실 정확성이 중요한 영역에서는 모델이 자체 지식만으로 답변하는 방식보다, 저장된 정책 데이터와 검색 결과를 근거로 답변하는 방식이 더 적합하다. 검색 증강 생성은 외부 지식 저장소에서 관련 정보를 검색한 뒤 이를 생성 모델의 입력으로 활용하는 접근으로, 지식 기반 질의응답에서 활용도가 높다[10].

본 프로젝트의 챗봇은 사용자의 질문을 기반으로 관련 정책 후보를 검색하고, 저장된 정책 상세 정보와 evidence를 바탕으로 답변을 생성하도록 설계하였다. 또한 모델이 후보 정책 밖의 임의 정책을 생성하지 않도록 후보 정책 allowlist를 적용하고, OpenAI 응답 실패나 파싱 실패 시 정책 후보 기반 fallback 답변을 제공한다.

### 5. LLM 응답 한계와 보조적 활용 필요성

LLM은 자연스러운 답변을 생성할 수 있지만, 실제와 다른 내용을 그럴듯하게 생성하는 환각 문제가 발생할 수 있다[11]. 복지 정책 정보는 신청 자격, 신청 기간, 제출 서류와 같이 사용자의 의사결정에 직접 영향을 주기 때문에, AI가 사실과 다른 내용을 생성하지 않도록 입력 데이터와 응답 범위를 제한하는 설계가 필요하다.

본 프로젝트에서는 AI가 모든 추천 판단과 정책 상담을 단독으로 수행하지 않도록 설계하였다. 추천 기능에서는 먼저 룰 기반 후보 선별과 점수 계산을 수행한 뒤, AI는 상위 후보에 대한 보조 점수와 추천 사유를 생성한다. 챗봇 기능에서도 저장된 정책 후보와 evidence 안에서만 답변하도록 제한하고, 최종 자격 판정이나 신청 가능 여부는 공식 안내를 확인해야 함을 전제로 하였다.

## 제 3 절 프로젝트 목적 및 범위

본 프로젝트의 목적은 분산된 청년 복지 정책 정보를 하나의 플랫폼에서 통합 제공하고, 사용자 개인 조건을 기반으로 적합한 정책을 추천하는 것이다. 또한 추천 결과의 근거를 함께 제공하고, 정책 검색, 챗봇 상담, 알림, 관리자 운영 기능을 연계하여 사용자가 정책을 발견하고 이해하며 활용할 수 있는 서비스 환경을 구현하는 것을 목표로 하였다.

프로젝트 범위는 다음과 같다.

1. 청년 복지 정책 통합 검색 제공
2. 사용자 조건 기반 맞춤형 추천 제공
3. 추천 사유 제공을 통한 설명 가능성 확보
4. 챗봇과 알림을 통한 정책 활용 흐름 지원
5. 관리자 기능을 통한 정책 데이터 품질 관리
6. AWS 기반 배포 및 운영 환경 구성

# 제 2 장 본론

## 제 1 절 프로젝트 최종 목표

본 프로젝트의 핵심 목표는 여러 기관에 분산된 청년 복지 정책 정보를 하나의 플랫폼에서 통합 제공하고, 사용자 개인 조건을 기반으로 AI 보조 맞춤형 정책 추천을 제공하는 것이다. 이를 위해 단순한 정책 목록 제공을 넘어 정책 데이터 수집과 정규화, 개인화 추천, 추천 근거 제공, 챗봇 상담, 알림, 관리자 운영 기능을 포함하는 통합 플랫폼을 목표로 설정하였다.

### 1. 청년 복지 정책 통합 플랫폼 구축

청년 복지 정책은 중앙정부, 지방자치단체, 공공기관 등 다양한 주체에 의해 제공되며, 출처마다 데이터 형식과 분류 기준이 다르다. 본 프로젝트는 이러한 정책 정보를 하나의 내부 모델로 통합하여 사용자가 정책 출처와 관계없이 동일한 기준으로 검색, 필터링, 상세 조회할 수 있도록 하였다.

### 2. AI 기반 개인 맞춤형 정책 추천 제공

사용자의 연령, 거주 지역, 소득 수준, 취업 상태, 가구 형태, 관심 분야, 우선순위에 따라 적합한 정책이 달라질 수 있다. 본 프로젝트에서는 사용자 프로필과 정책 조건을 비교하여 후보를 선별하고, 룰 기반 점수와 OpenAI API 기반 보조 평가 결과를 결합하여 개인 맞춤형 추천 결과를 제공하도록 구현하였다.

### 3. 추천 사유 및 핵심 정보 제공

복지 정책은 신청 조건과 제출 서류, 신청 기간, 신청 방법이 복잡하기 때문에 사용자가 정책명만 보고 적합성을 판단하기 어렵다. 본 프로젝트는 추천 결과와 함께 추천 사유, 지원 대상, 신청 기간, 지원 내용, 신청 방법 등을 제공하여 사용자가 추천 결과를 이해하고 실제 신청 여부를 판단할 수 있도록 지원하였다.

### 4. 정책 탐색부터 신청 준비까지 이어지는 사용자 경험 제공

사용자는 정책 검색이나 추천 이후에도 신청 자격, 제출 서류, 공식 신청 경로 등에 대해 추가 정보를 필요로 할 수 있다. 본 프로젝트에서는 정책 상세 화면에서 챗봇 상담으로 이어지는 흐름을 제공하고, 북마크와 알림 기능을 통해 사용자가 관심 정책을 다시 확인할 수 있도록 하였다.

### 5. 정책 데이터 품질 관리 및 운영 신뢰성 확보

외부 공공데이터를 활용하는 서비스는 데이터 출처 변경, 중복 정책, 유효하지 않은 링크, 신청 기간 불일치와 같은 문제가 발생할 수 있다. 본 프로젝트에서는 관리자 대시보드를 통해 수집 상태, 정책 오류 제보, 중복 후보, 링크 검토, 추천 및 알림 상태를 확인할 수 있도록 하여 통합 플랫폼의 데이터 신뢰성을 관리할 수 있는 기반을 마련하였다.

## 제 2 절 프로젝트 설계

### 1. 전체 시스템 구조

본 프로젝트는 프론트엔드, 백엔드 API, 데이터 저장소, 외부 API 연동, 운영 배포 계층으로 구성된다. 프론트엔드는 React와 Vite 기반으로 구현하여 사용자의 정책 검색, 상세 조회, 프로필 관리, 맞춤 추천, 챗봇, 알림, 관리자 화면을 제공한다. 백엔드는 Spring Boot 기반 API 서버로 구성하여 인증, 정책 조회, 추천 계산, 챗봇 응답, 알림 처리, 관리자 기능을 담당한다.

데이터 저장소는 PostgreSQL 16을 중심으로 구성하였으며, 정책 정보, 사용자 정보, 추천 결과, 알림, 채팅 기록, 운영 데이터를 저장한다. 또한 pgvector를 활용하여 정책 문서 임베딩과 챗봇의 의미 기반 검색을 보조할 수 있도록 구성하였다. 인증 상태, 요청 제한, 작업 lock 등 빠른 상태 관리가 필요한 기능에는 Redis 호환 저장소를 활용하였다.

[그림 1] 전체 시스템 아키텍처
사용자는 React 기반 웹 프론트엔드를 통해 서비스에 접근하며, Spring Boot API 서버는 정책 검색, 추천, 챗봇, 알림, 관리자 기능을 처리한다. 정책 및 사용자 데이터는 PostgreSQL에 저장되고, 빠른 상태 관리는 Redis 호환 저장소를 통해 처리된다.

### 2. 정책 데이터 통합 구조

정책 데이터 통합 구조는 출처별 데이터 형식 차이를 사용자에게 노출하지 않고, 하나의 검색 및 추천 기준으로 제공하기 위해 설계하였다. 본 프로젝트에서는 온통청년, 복지로 중앙부처, 복지로 지자체, Gov24 API를 수집 대상으로 두고, 출처별로 다른 정책 형식과 분류 체계를 내부 서비스 모델로 통합하였다.

정책 데이터는 수집 후 원문 payload를 보존하고, 정규화 mapper를 통해 정책 기본 정보, 상세 정보, 지역 정보, 태그, 지원조건 fact로 분리 저장된다. 이렇게 저장된 데이터는 정책 검색, 상세 조회, 추천 후보 추출, 챗봇 답변, 관리자 검토 기능에서 공통적으로 활용된다.

출처별 정책 분류가 내부 대표 분류와 맞지 않는 경우를 줄이기 위해 정책명, 지원 내용, 원천 분류를 함께 검토하는 보수적 보정 규칙도 적용하였다. 예를 들어 주거비·월세·기숙사 지원은 주거 분야로, 장학금·학자금 지원은 교육·직업훈련 분야로, 창업공간·사업장 임차료 지원은 일자리 분야로 분류되도록 하였다. 단일 분야로 단정하기 어려운 복합 정책은 자동 변경하지 않고 관리자 검토 대상으로 남겨 데이터 품질과 추천 품질 사이의 균형을 유지하였다.

정책 데이터 통합 과정은 외부 API 수집, 원문 데이터 보존, 내부 정책 모델 변환, 검색·추천·챗봇 공통 활용의 흐름으로 구성된다. 해당 구조는 전체 시스템 아키텍처와 맞춤 추천 파이프라인 도표에서 함께 설명한다.

### 3. 사용자 프로필 및 개인화 기준 설계

사용자 프로필은 개인 맞춤형 추천을 위한 핵심 입력값으로 설계하였다. 프로필에는 연령, 지역, 소득 수준, 취업 상태, 가구 형태, 관심 분야 등이 포함된다. 또한 사용자가 중요하게 생각하는 정책 유형을 우선순위로 설정할 수 있도록 하여 동일한 조건의 사용자라도 선호에 따라 다른 추천 결과를 받을 수 있도록 하였다.

사용자 프로필과 우선순위 정보는 추천 기능뿐 아니라 정책 탐색, 알림, 챗봇 상담 흐름에도 연결된다. 선택 정보와 민감 정보는 사용자 동의 흐름과 함께 관리하여 개인화 기능과 개인정보 보호 요구를 함께 고려하였다.

### 4. AI 개인화 추천 파이프라인 설계

AI 개인화 추천 파이프라인은 본 프로젝트의 핵심 설계 요소이다. 추천 시스템은 AI가 모든 판단을 단독으로 수행하는 방식이 아니라, 명확한 조건은 룰 기반으로 먼저 처리하고, 정책 내용과 사용자 상황의 적합성처럼 정성적 해석이 필요한 부분은 AI가 보조하는 하이브리드 구조로 설계하였다.

추천 파이프라인은 사용자 프로필 기반 후보 추출, 룰 기반 점수 계산, 사용자 우선순위 가중치 적용, OpenAI API 기반 보조 점수 및 추천 사유 생성, 최종 점수 산출 및 정렬의 순서로 구성된다. OpenAI API 호출이 불가능하거나 응답 파싱에 실패하는 경우에도 rule-only fallback으로 추천 결과를 제공할 수 있도록 설계하였다.

[그림 2] AI 개인화 추천 파이프라인
사용자 프로필과 정책 데이터가 입력되면 후보 정책을 추출하고, 룰 기반 점수와 우선순위 가중치를 계산한 뒤 OpenAI API 기반 보조 점수와 추천 사유를 결합하여 최종 추천 결과를 생성한다.

### 5. 챗봇 기반 정책 상담 구조

챗봇 기능은 사용자가 자연어로 정책 관련 질문을 입력하고 관련 정책 정보를 기반으로 답변을 받을 수 있도록 설계하였다. 챗봇은 사용자의 질문을 바탕으로 관련 정책 후보를 검색하고, 저장된 정책 상세 정보와 evidence를 입력으로 사용한다. OpenAI API는 해당 후보 안에서만 답변을 생성하도록 제한되며, 후보 밖 정책 ID를 임의로 생성하지 않도록 allowlist 검증을 적용하였다.

또한 정책 상세 화면에서 특정 정책을 기준으로 "AI와 신청 준비하기" 흐름을 제공한다. 이 기능은 사용자가 관심 정책을 선택한 뒤 신청 자격, 신청 방법, 제출 서류, 공식 링크 등을 챗봇을 통해 확인할 수 있도록 지원한다.

챗봇 상담 구조는 저장된 정책 데이터와 OpenAI API를 함께 활용하되, 답변 범위를 후보 정책과 evidence 안으로 제한하는 방식으로 구현하였다. 별도 도표를 추가하지 않고, 주요 구현 내용의 챗봇 화면과 API 사용 내역에서 동작 범위를 설명한다.

### 6. 사용자 서비스 흐름

사용자 서비스 흐름은 정책을 발견하고, 이해하고, 저장하고, 다시 확인하는 과정을 중심으로 설계하였다. 비로그인 사용자는 기본적인 정책 검색과 상세 조회를 이용할 수 있고, 로그인 사용자는 프로필과 우선순위를 입력한 뒤 개인 맞춤형 정책 추천을 받을 수 있다.

사용자는 추천 결과에서 정책 상세 정보를 확인하거나 북마크할 수 있으며, 정책과 관련된 질문이 있는 경우 챗봇 상담으로 이어질 수 있다. 알림 기능은 사용자가 추천 정책이나 관심 정책을 놓치지 않고 다시 확인할 수 있도록 지원한다.

[그림 3] 사용자 서비스 흐름
사용자는 정책 검색과 상세 조회를 통해 기본 정보를 확인하고, 로그인 후 프로필과 우선순위를 설정하여 맞춤 추천, 챗봇 상담, 알림 기능으로 이어지는 흐름을 이용한다.

### 7. 관리자 운영 흐름

관리자 운영 흐름은 정책 데이터 품질과 서비스 신뢰성을 유지하기 위해 설계하였다. 관리자는 대시보드를 통해 정책 수집 상태, 정책 오류 제보, 중복 정책 후보, 링크 검토, 추천 상태, 알림 상태 등을 확인할 수 있다. 이를 통해 외부 데이터 기반 서비스에서 발생할 수 있는 품질 문제를 운영자가 파악하고 조치할 수 있도록 하였다.

[그림 4] 관리자 운영 흐름
관리자는 대시보드에서 정책 수집 상태, 오류 제보, 중복 후보, 링크 검토, 추천 및 알림 상태를 확인하고 필요한 운영 조치를 수행한다.

### 8. 배포 및 운영 구조

배포 및 운영 구조는 실제 서비스 운영과 향후 확장을 고려하여 설계하였다. 프론트엔드는 빌드된 정적 파일을 nginx를 통해 제공하고, API 요청은 Spring Boot 백엔드 애플리케이션으로 프록시한다. 운영 데이터는 RDS PostgreSQL에 저장되며, 인증 상태, 요청 제한, 작업 lock 등 빠른 접근이 필요한 상태 정보는 ElastiCache Valkey를 활용하도록 구성하였다.

최종 제출 및 시연 기준 운영 구조는 ALB 뒤에 두 대의 EC2 웹 노드를 두는 방식이다. 두 EC2는 동일한 애플리케이션을 실행하되, 정책 수집과 알림 발송 같은 스케줄러 작업은 중복 실행을 방지하기 위해 한 노드에서만 활성화하도록 설계하였다.

배포 및 운영 구조는 전체 시스템 아키텍처 도표에서 함께 설명한다. 본문에서는 ALB, EC2 웹 노드, RDS PostgreSQL, ElastiCache Valkey, nginx, Docker Compose의 역할을 중심으로 정리하였다.

### 2. 외부 API 및 연동 서비스 사용 내역

본 프로젝트는 청년 복지 정책 정보를 통합적으로 제공하기 위해 여러 공공데이터 API와 외부 연동 서비스를 사용하였다. 정책 데이터 수집에는 온통청년 청년정책 API, 복지로 중앙부처 복지서비스 API, 복지로 지자체 복지서비스 API, Gov24 공공서비스 API를 활용하였다. AI 기반 추천 사유 생성과 챗봇 답변 생성에는 OpenAI API를 사용하였으며, 알림 기능에는 SMTP 메일 발송과 Web Push를 활용하였다.

외부 API 키와 인증 정보는 소스 코드에 직접 작성하지 않고 환경변수를 통해 관리하였다. 또한 OpenAI API 호출 시 이름, 이메일, 생년월일과 같은 직접 식별 정보는 입력에 포함하지 않고, 연령대, 지역, 소득 구간, 취업 상태와 같은 범주형 정보와 후보 정책 요약 정보를 중심으로 활용하였다[6][7].

운영 관측과 알림에는 AWS CloudWatch, SNS, Route53 health check, ALB target health 조회를 활용하였다. 이 항목들은 사용자 기능을 위한 외부 정책 API는 아니지만, 배포 환경의 상태 확인과 장애 알림을 위한 운영 연동 요소로 사용하였다.

## 제 4 절 주요 구현 내용

### 1. 정책 통합 검색 및 상세 조회 기능

정책 통합 검색 기능은 여러 출처에서 수집한 청년 복지 정책을 사용자가 하나의 화면에서 검색하고 비교할 수 있도록 구현하였다. 사용자는 키워드 검색과 함께 지역, 분야, 신청 상태, 출처, 정렬 조건을 조합하여 정책을 탐색할 수 있다.

정책 목록에서는 정책명, 소관 기관, 지원 지역, 신청 상태, 주요 요약 정보를 확인할 수 있도록 하였고, 상세 화면에서는 지원 대상, 신청 기간, 지원 내용, 신청 방법, 관련 링크 등 실제 신청 판단에 필요한 정보를 제공하였다.

[그림 5] 메인 화면
서비스 첫 화면에서 사용자는 주요 정책 탐색 진입점과 개인화 서비스 접근 흐름을 확인할 수 있다.

[그림 6] 정책 검색 및 필터 화면
사용자는 키워드, 지역, 분야, 신청 상태, 출처 조건을 조합하여 정책을 검색하고 비교할 수 있다.

[그림 7] 정책 상세 화면
정책 상세 화면에서는 지원 대상, 신청 기간, 지원 내용, 신청 방법, 관련 링크 등 신청 판단에 필요한 핵심 정보를 확인할 수 있다.

### 2. 사용자 인증, 프로필 및 개인화 기준 관리 기능

사용자 개인화 서비스를 제공하기 위해 회원가입, 로그인, 로그아웃, 토큰 갱신, 비밀번호 재설정 기능을 구현하였다. 인증은 JWT 기반으로 처리하였으며, refresh token은 HttpOnly 쿠키를 활용하여 관리하였다.

마이페이지에서는 사용자가 자신의 프로필 정보를 관리할 수 있도록 하였다. 프로필에는 연령, 지역, 소득 수준, 취업 상태, 가구 형태, 관심 분야 등 개인화 추천에 필요한 정보가 포함된다. 또한 사용자는 주거, 일자리, 교육, 금융, 문화, 가족, 마감임박 등 자신에게 중요한 정책 유형을 우선순위로 설정할 수 있다.

[그림 8] 마이페이지 프로필 및 우선순위 설정 화면
사용자는 마이페이지에서 추천에 필요한 프로필 정보와 정책 유형 우선순위를 설정할 수 있다.

### 3. AI 기반 개인 맞춤형 추천 기능

AI 기반 개인 맞춤형 추천 기능은 후보 정책 조회, 룰 기반 점수 계산, OpenAI API 기반 보조 점수 및 추천 사유 생성, 추천 결과 저장 및 조회의 흐름으로 구현하였다. 먼저 사용자의 연령, 지역, 소득, 관심 분야 등 비교 가능한 조건을 바탕으로 정책 후보를 추출한다. 이후 관심 분야 일치 여부, 대상 유형 일치 여부, 마감 임박 여부, 사용자 우선순위 등을 반영하여 룰 기반 점수를 계산한다.

OpenAI API는 상위 후보 정책에 대해 보조 점수와 추천 사유를 생성하는 데 사용하였다. 이때 직접 식별 정보는 제외하고, 연령대, 지역, 소득 구간, 관심 분야와 같은 범주형 정보를 중심으로 사용하였다. 최종 추천 결과는 룰 기반 점수와 AI 점수를 결합한 final score를 기준으로 정렬된다.

[그림 9] 맞춤 추천 결과 화면
맞춤 추천 결과 화면에서는 사용자의 조건에 따라 정렬된 추천 정책과 추천 사유를 함께 확인할 수 있다.

### 4. 챗봇 기반 정책 상담 및 신청 준비 코칭 기능

챗봇 기능은 사용자가 자연어로 정책 관련 질문을 입력하고 관련 정책 정보를 기반으로 답변을 받을 수 있도록 구현하였다. 챗봇은 질문을 바탕으로 관련 정책 후보를 찾고, 저장된 정책 정보를 근거로 답변을 생성한다. 답변에는 관련 정책 목록과 정책 상세 페이지로 이동할 수 있는 참조 정보가 포함된다.

또한 정책 상세 화면에서 특정 정책을 기준으로 "AI와 신청 준비하기" 흐름을 제공하였다. 이 기능은 사용자가 관심 정책을 선택한 뒤, 해당 정책에 대한 신청 자격, 신청 방법, 제출 서류, 공식 링크 등을 챗봇을 통해 확인할 수 있도록 지원한다.

[그림 10] 챗봇 정책 상담 화면
챗봇 화면에서는 사용자가 자연어로 정책 관련 질문을 입력하고, 관련 정책 참조와 함께 답변을 받을 수 있다.

### 5. 알림 및 사용자 재방문 지원 기능

알림 기능은 사용자가 추천 정책 정보를 지속적으로 확인할 수 있도록 지원하기 위해 구현하였다. 알림은 추천 정책 안내를 중심으로 구성하고, 인앱 알림함을 통해 사용자가 놓친 정책 정보를 다시 확인할 수 있도록 하였다. 또한 웹푸시 구독 기능을 구현하여 브라우저 기반 알림 확장이 가능하도록 하였다.

[그림 11] 알림함 화면
알림함은 추천 정책 및 주요 정책 정보를 사용자가 다시 확인할 수 있도록 지원한다.

### 6. 관리자 대시보드 및 정책 품질 관리 기능

관리자 대시보드는 통합 플랫폼의 정책 데이터 품질과 운영 상태를 관리하기 위해 구현하였다. 관리자는 관리자 화면을 통해 정책 수집 상태, 검색 및 추천 상태, 정책 오류 제보, 서비스 문의, 중복 정책 후보, 링크 검토, 알림 상태 등을 확인할 수 있다.

정책 오류 제보 기능과 연계하여 사용자가 신고한 잘못된 정책 정보는 관리자 대시보드에서 확인하고 처리할 수 있도록 하였다. 또한 중복 정책 후보와 링크 검토 항목을 관리할 수 있도록 하여 외부 데이터 수집 과정에서 발생할 수 있는 품질 문제를 운영자가 확인할 수 있게 하였다.

관리자 기능은 정책 데이터의 정확성과 신뢰성을 유지하기 위한 운영 흐름을 포함한다. 정책 분류가 명확하지 않은 항목은 자동으로 단정하지 않고 관리자 검토 대상으로 남기며, 명확한 오분류와 유효하지 않은 링크는 운영자가 확인할 수 있도록 하였다. 이를 통해 정책 검색, 추천, 챗봇에서 사용하는 데이터의 품질을 지속적으로 관리할 수 있는 구조를 마련하였다.

[그림 12] 관리자 대시보드 화면
관리자 대시보드는 정책 수집, 정책 품질, 추천, 알림 등 운영 상태를 한 화면에서 확인할 수 있도록 제공된다.

### 7. 서비스 배포 및 운영 환경

서비스 배포 환경은 실제 운영 가능성을 고려하여 구성하였다. 프론트엔드는 빌드된 정적 파일을 nginx를 통해 제공하고, API 요청은 Spring Boot 백엔드 애플리케이션으로 프록시하도록 구성하였다. 백엔드 애플리케이션은 Docker Compose 기반으로 실행되며, 운영 데이터는 AWS RDS PostgreSQL에 저장된다.

Redis 호환 저장소로는 ElastiCache Valkey를 사용하여 인증 상태, 요청 제한, 작업 lock 등을 관리하도록 구성하였다. 제출 및 시연 기준 운영 구조는 ALB와 두 대의 EC2 웹 노드를 활용하는 형태로 구성하고, 스케줄러 작업은 중복 실행을 방지하기 위해 한 노드에서만 활성화하도록 설계하였다.

# 제 3 장 결론

## 제 1 절 프로젝트 구현 내용 및 결과

본 프로젝트는 청년 복지 정책 정보를 통합적으로 제공하고, 사용자 개인 조건에 기반한 맞춤형 정책 추천을 제공하는 웹 플랫폼으로 구현되었다. 구현 결과, 사용자는 하나의 플랫폼에서 정책 검색, 상세 조회, 프로필 관리, 개인 맞춤형 추천, 챗봇 상담, 알림 확인까지 이어지는 흐름을 이용할 수 있게 되었다. 또한 관리자는 정책 데이터와 서비스 상태를 확인할 수 있어, 통합 플랫폼의 운영과 데이터 품질 관리를 함께 수행할 수 있다.

주요 구현 결과는 다음과 같다.

1. 여러 출처의 청년 복지 정책 정보를 수집하고 내부 정책 모델로 통합하였다.
2. 키워드, 지역, 분야, 신청 상태, 출처 기반 정책 검색과 상세 조회 기능을 구현하였다.
3. 사용자 프로필과 우선순위를 기반으로 룰 기반 점수와 OpenAI 보조 평가를 결합한 추천 기능을 구현하였다.
4. 추천 결과에 추천 사유와 핵심 정보를 함께 제공하여 설명 가능한 추천을 구현하였다.
5. 저장된 정책 정보를 기반으로 답변하는 챗봇 상담과 신청 준비 코칭 기능을 구현하였다.
6. 인앱 알림, 이메일 알림, 웹푸시 구독 구조를 통해 사용자 재방문을 지원하였다.
7. 관리자 대시보드를 통해 수집 상태, 정책 오류, 중복 후보, 링크 검토, 추천 및 알림 상태를 관리할 수 있도록 하였다.
8. AWS EC2, RDS, ElastiCache, nginx, Docker Compose 기반 운영 환경을 구성하였다.

## 제 2 절 테스트 및 검증 결과

구현된 기능의 정상 동작을 확인하기 위해 백엔드 단위 테스트, 통합 테스트, 프론트엔드 정적 검증, 브라우저 기반 사용자 흐름 테스트, 운영 API 점검을 수행하였다. 백엔드 테스트는 서비스 로직, 인증, 추천, 챗봇, 알림 관련 기능의 회귀를 확인하는 데 사용하였고, 통합 테스트는 PostgreSQL과 Redis가 포함된 실제 실행 환경에 가까운 조건에서 API 흐름을 검증하는 데 사용하였다.

프론트엔드는 ESLint와 Vite build를 통해 문법 오류와 빌드 가능 여부를 확인하였으며, Playwright 기반 브라우저 테스트를 통해 로그인, 정책 검색, 상세 조회, 추천, 챗봇, 알림 등 주요 사용자 흐름을 검증하였다. 운영 환경에서는 health check, 인증, 추천, 북마크, 로그아웃, 관리자 기능, 수집 상태, 알림 상태 등을 운영 환경 점검 스크립트와 관측 스크립트로 확인하였다.

| 운영 API 점검 | health check, 인증, 추천, 북마크, 로그아웃 등 운영 API 동작 확인 | 운영 환경 점검 스크립트 |
| 관리자 기능 검증 | 수집 상태, 정책 품질, 추천, 알림 운영 상태 확인 | 관리자 화면 점검 및 운영 관측 스크립트 |
| 배포 환경 검증 | nginx, Docker Compose, RDS, ElastiCache 기반 운영 접근성 확인 | health check 및 운영 관측 스크립트 |

검증 결과 주요 사용자 기능과 관리자 운영 기능이 정상적으로 동작함을 확인하였다. 또한 운영 환경에서도 애플리케이션 health check와 주요 API 점검이 통과하여, 본 프로젝트가 단순한 로컬 기능 구현을 넘어 실제 배포 환경을 고려한 통합 플랫폼 형태로 구현되었음을 확인하였다.

운영 응답성은 최종 배포 환경에서 주요 흐름이 정상적으로 완료되는지 확인하기 위한 보조 검증 지표로 측정하였다. 정책 조회와 검색 중심의 공개 읽기 API, 로그인과 토큰 갱신, 추천 조회, 챗봇 질문, 통합 사용자 여정을 각각 구분하여 확인하였고, OpenAI API가 포함되는 추천 재계산과 챗봇 답변은 일반 조회 API와 분리하여 해석하였다.

[표 5] 운영 환경 응답성 검증 요약

| 검증 항목 | 검증 범위 | 주요 결과 | 오류 및 제한 응답 |
|----------|----------|----------|------------------|
| 공개 읽기 API | 정책 목록, 검색, 추천순, 상세, 자동완성 | endpoint-only p95 42ms 이하 | 오류 0, 429 0 |
| 인증 흐름 | 로그인, 토큰 갱신, 프로필 조회, 로그아웃 | 로그인 p95 200.7ms, 토큰 갱신 p95 47.7ms | 오류 0, 429/A010 0 |
| 추천 흐름 | 추천 조회, 공유 refresh, 개인 refresh | 저장 추천 조회 312.8ms 이하, 공유 refresh 4065.0ms, cached refresh 437.8ms, 개인 refresh 4552.8ms | 오류 0, 429/R004 0 |
| 챗봇 흐름 | 대표 질문 3개 | 메시지 전송 최대 4225.4ms, POLICY_GROUNDED 2건과 APPLICATION_COACHING 1건 | 오류 0, rate-limit 0 |
| 통합 사용자 여정 | 가입부터 검색, 추천, 북마크, 챗봇, 로그아웃까지 18단계 | 전체 측정 API 시간 8941.9ms, 비-AI 1861.6ms, AI 구간 7080.4ms | 오류 0, rate-limit 0 |
| 읽기 API 부하 경계 | 동일 출처 혼합 읽기 부하 | 약 2.4 rps까지 오류 없이 처리, 약 4.8 rps에서 rate-limit 발생 | 실패 모드는 429 rate-limit |

통합 사용자 여정에서는 가입, 로그인, 프로필 설정, 정책 검색, 상세 조회, 추천 조회, 북마크, 챗봇 질문, 로그아웃까지 18개 단계가 모두 성공하였다. 추천 생성과 챗봇 답변은 외부 AI API 호출을 포함하므로 일반 조회 API보다 응답 시간이 길게 나타났으며, 이는 AI 기반 기능의 특성으로 분리하여 해석하였다. 검증 후에도 ALB 대상 두 대는 모두 healthy 상태를 유지하였고, 사용자 영향 5xx, 장시간 DB 대기, 애플리케이션 재시작은 확인되지 않았다.

## 제 3 절 활용 방안 및 기대효과

### 1. 청년 복지 정책 접근성 향상

본 플랫폼은 여러 기관에 분산되어 있는 청년 복지 정책 정보를 하나의 서비스에서 검색하고 확인할 수 있도록 제공한다. 이를 통해 사용자는 개별 기관의 웹사이트를 직접 방문하기 전에 주요 정책 정보를 한곳에서 우선 확인할 수 있다.

### 2. 개인 맞춤형 추천을 통한 정책 탐색 비용 절감

사용자는 많은 정책 목록을 일일이 확인하지 않고도 자신의 조건과 관련성이 높은 정책을 먼저 확인할 수 있다. 또한 추천 사유와 핵심 정보를 함께 제공함으로써 추천 결과를 이해하고 실제 신청 여부를 판단하는 데 도움을 받을 수 있다.

### 3. 복지 사각지대 해소 가능성

청년 복지 정책은 존재하더라도 사용자가 해당 정보를 제때 알지 못하면 실제 수혜로 이어지기 어렵다. 본 플랫폼은 개인화 추천과 알림 기능을 통해 사용자가 자신에게 관련된 정책 정보를 다시 확인할 수 있도록 지원한다.

### 4. 사용자 행동 및 추천 데이터 기반 서비스 고도화

정책 검색, 상세 조회, 추천 결과, 북마크, 알림 등 사용자의 서비스 이용 과정에서 발생하는 데이터는 향후 추천 알고리즘 개선, 알림 기준 개선, 정책 수요 분석에 활용될 수 있다.

### 5. 공공서비스 추천 플랫폼으로의 확장 가능성

본 프로젝트의 핵심 구조는 청년 복지 정책에만 한정되지 않는다. 사용자 조건 기반 후보 추출, 룰 기반 필터링, AI 추천 사유 생성 구조는 취약계층 지원, 지역 주민 지원, 창업 지원, 교육 지원 등 다양한 공공서비스 추천 플랫폼으로 확장할 수 있다.

## 제 4 절 한계점 및 향후 개선 방향

본 프로젝트는 청년 복지 정책 정보를 통합하고 사용자 조건 기반 맞춤형 추천을 제공하는 플랫폼을 구현하였지만, 공공데이터 기반 서비스와 AI 보조 기능의 특성상 지속적인 개선이 필요한 영역도 존재한다.

첫째, 정책 데이터는 외부 API 제공 상태와 원본 데이터 품질에 영향을 받기 때문에 최신성 및 정확성을 지속적으로 점검해야 한다. 향후에는 정책 변경 감지, 중복 정책 탐지, 유효하지 않은 링크 검토, 신청 기간 불일치 탐지를 더욱 자동화할 수 있다.

둘째, 추천 품질을 더 높이기 위해서는 실제 사용자의 검색, 조회, 북마크, 알림 반응과 같은 데이터가 충분히 축적되어야 한다. 향후에는 비식별·집계된 사용자 반응 데이터를 기반으로 추천 가중치와 알림 기준을 개선할 수 있다.

셋째, AI 추천 사유와 챗봇 답변은 정책 이해를 돕는 보조 정보로 제공되어야 하며, 최종 자격 판단이나 신청 가능 여부는 공식 정책 안내를 통해 확인해야 한다. 향후에는 챗봇 답변의 근거 표시와 신청 준비 코칭 기능을 강화하여 사용자가 정책 탐색에서 실제 신청 준비까지 더 자연스럽게 이어갈 수 있도록 개선할 수 있다.

넷째, 알림 기능은 현재 추천 알림과 인앱 알림, 웹푸시 구독 구조를 중심으로 구현되어 있다. 향후에는 신규 정책 등록, 신청 마감 임박, 북마크 정책 상태 변경 등 다양한 정책 이벤트 기반 알림으로 확장할 수 있다.

다섯째, 운영 인프라는 제출 및 시연 기준으로 ALB와 두 대의 EC2 웹 노드를 활용할 수 있도록 설계하였지만, 장기 운영 단계에서는 사용자 수와 트래픽 변화에 따라 인프라 비용과 성능을 함께 조정해야 한다.
