# 결과보고서 보강 본문 초안

이 문서는 결과보고서에 바로 반영할 수 있는 보강 문단 초안이다.
최종 문서에서는 학교 양식, 그림 번호, 표 번호에 맞춰 조정한다.

## 제1장 제2절 관련 기술 및 선행연구 보강 초안

### 1. 공공데이터 통합 및 정책 데이터 정규화

공공 복지 정책 데이터는 제공 기관과 API에 따라 데이터 구조, 명칭, 분류 체계가 다르게 제공된다. 온통청년 API는 청년 정책 중심의 정책명, 정책 키워드, 정책 분류, 신청 기간 정보를 제공하고, 복지로 API는 중앙부처 및 지자체 복지서비스의 지원대상, 선정기준, 신청방법 정보를 제공한다. Gov24 공공서비스 API는 다양한 정부 혜택의 목록, 상세 정보, 지원조건을 제공한다. 이러한 데이터를 하나의 서비스에서 활용하기 위해서는 출처별 응답 구조를 내부 정책 모델로 변환하고, 지역, 분야, 대상, 신청 상태 등을 동일한 기준으로 정리하는 과정이 필요하다.

본 프로젝트에서는 온통청년, 복지로 중앙부처, 복지로 지자체, Gov24 API에서 수집한 정책 데이터를 내부 정책 테이블과 상세 정보 테이블, 지역 정보, 태그, 지원조건 fact로 분리하여 저장하였다. 이를 통해 출처가 다른 정책이라도 사용자는 동일한 검색 필터와 상세 화면에서 확인할 수 있으며, 추천과 챗봇 기능도 같은 정책 데이터 기반으로 동작할 수 있도록 설계하였다.

### 2. 개인화 추천 시스템과 하이브리드 추천 방식

개인화 추천 시스템은 많은 정보 중 사용자에게 적합한 항목을 우선적으로 제시하는 기술이다. 일반적인 콘텐츠나 상품 추천과 달리 복지 정책 추천은 사용자의 선호뿐만 아니라 연령, 거주 지역, 소득 수준, 취업 상태, 가구 형태와 같은 자격 조건이 중요하게 작용한다. 따라서 단순한 인기순 또는 키워드 유사도만으로는 사용자가 실제로 신청 가능한 정책을 효과적으로 찾기 어렵다.

하이브리드 추천 시스템 연구는 여러 추천 방식을 결합하여 단일 방식의 한계를 보완할 수 있음을 제시한다. 본 프로젝트는 이러한 관점을 청년 복지 정책 추천에 적용하여, 명확한 조건은 룰 기반으로 먼저 반영하고, 정책 내용과 사용자 상황의 정성적 적합성은 OpenAI API를 활용한 보조 평가와 추천 사유 생성으로 보완하였다. 이를 통해 추천 결과의 계산 가능성과 설명 가능성을 함께 확보하고자 하였다.

### 3. 설명 가능한 추천

복지 정책 추천에서는 단순히 정책 목록을 제시하는 것만으로 충분하지 않다. 사용자는 해당 정책이 자신에게 왜 추천되었는지, 어떤 조건이 자신의 상황과 연결되는지 이해해야 실제 신청 여부를 판단할 수 있다. 설명 가능한 추천 연구는 추천 결과와 함께 이유를 제공함으로써 추천 시스템의 투명성, 신뢰성, 사용자 이해도를 높일 수 있음을 강조한다.

본 프로젝트에서는 추천 결과에 최종 점수뿐만 아니라 추천 사유를 함께 제공하도록 구현하였다. 추천 사유는 정책명만 나열하는 방식이 아니라 사용자의 지역, 관심 분야, 소득 구간, 취업 상태 등 범주형 조건과 정책의 지원 내용이 어떻게 연결되는지를 설명하는 데 초점을 두었다. 이를 통해 사용자는 추천 목록을 단순히 확인하는 데 그치지 않고, 자신에게 해당 정책이 필요한 이유를 함께 이해할 수 있다.

### 4. RAG 및 LLM 기반 정책 상담

LLM은 긴 문서를 요약하고 자연어 질의응답을 제공하는 데 강점을 가진다. 그러나 복지 정책과 같이 사실 정확성이 중요한 영역에서는 모델이 자체 지식만으로 답변하는 방식보다, 저장된 정책 데이터와 검색 결과를 근거로 답변하는 방식이 더 적합하다. 검색 증강 생성(Retrieval-Augmented Generation, RAG)은 외부 지식 저장소에서 관련 정보를 검색한 뒤 이를 생성 모델의 입력으로 활용하는 접근으로, 지식 기반 질의응답에서 활용도가 높다.

본 프로젝트의 챗봇은 사용자의 질문을 기반으로 관련 정책 후보를 검색하고, 저장된 정책 상세 정보와 evidence를 바탕으로 답변을 생성하도록 설계하였다. 또한 모델이 후보 정책 밖의 임의 정책을 생성하지 않도록 후보 정책 allowlist를 적용하고, OpenAI 응답 실패나 파싱 실패 시 정책 후보 기반 fallback 답변을 제공한다. 이를 통해 챗봇을 공식 상담이나 신청 대행이 아니라 정책 탐색과 신청 준비를 돕는 보조 기능으로 제한하였다.

### 5. LLM 응답 한계와 보조적 활용 필요성

LLM은 자연스러운 답변을 생성할 수 있지만, 실제와 다른 내용을 그럴듯하게 생성하는 환각 문제가 발생할 수 있다. 복지 정책 정보는 신청 자격, 신청 기간, 제출 서류와 같이 사용자의 의사결정에 직접 영향을 주기 때문에, AI가 사실과 다른 내용을 생성하지 않도록 입력 데이터와 응답 범위를 제한하는 설계가 필요하다.

본 프로젝트에서는 AI가 모든 추천 판단과 정책 상담을 단독으로 수행하지 않도록 설계하였다. 추천 기능에서는 먼저 룰 기반 후보 선별과 점수 계산을 수행한 뒤, AI는 상위 후보에 대한 보조 점수와 추천 사유를 생성한다. 챗봇 기능에서도 저장된 정책 후보와 evidence 안에서만 답변하도록 제한하고, 최종 자격 판정이나 신청 가능 여부는 공식 안내를 확인해야 함을 전제로 하였다. 이러한 설계는 AI의 장점을 활용하되, 공공서비스 정보 제공에서 요구되는 신뢰성과 안전성을 함께 고려한 것이다.

## 제2장 제3절 외부 API 및 연동 서비스 사용 내역 초안

본 프로젝트는 청년 복지 정책 정보를 통합적으로 제공하기 위해 여러 공공데이터 API와 외부 연동 서비스를 사용하였다. 정책 데이터 수집에는 온통청년 청년정책 API, 복지로 중앙부처 복지서비스 API, 복지로 지자체 복지서비스 API, Gov24 공공서비스 API를 활용하였다. AI 기반 추천 사유 생성과 챗봇 답변 생성에는 OpenAI API를 사용하였으며, 알림 기능에는 SMTP 메일 발송과 Web Push를 활용하였다.

외부 API 키와 인증 정보는 소스 코드에 직접 작성하지 않고 환경변수를 통해 관리하였다. 또한 OpenAI API 호출 시 이름, 이메일, 생년월일과 같은 직접 식별 정보는 입력에 포함하지 않고, 연령대, 지역, 소득 구간, 취업 상태와 같은 범주형 정보와 후보 정책 요약 정보를 중심으로 활용하였다. API 호출 실패나 응답 파싱 실패가 발생하더라도 서비스가 중단되지 않도록 추천 기능은 룰 기반 fallback을 제공하고, 챗봇 기능은 정책 후보 기반 fallback 답변을 제공하도록 구현하였다.

## 제3장 제2절 테스트 및 검증 결과 강화 초안

구현된 기능의 정상 동작을 확인하기 위해 백엔드 단위 테스트, 통합 테스트, 프론트엔드 정적 검증, 브라우저 기반 사용자 흐름 테스트, 운영 API smoke test를 수행하였다. 백엔드 테스트는 서비스 로직, 인증, 추천, 챗봇, 알림 관련 기능의 회귀를 확인하는 데 사용하였고, 통합 테스트는 PostgreSQL과 Redis가 포함된 실제 실행 환경에 가까운 조건에서 API 흐름을 검증하는 데 사용하였다.

프론트엔드는 ESLint와 Vite build를 통해 문법 오류와 빌드 가능 여부를 확인하였으며, Playwright 기반 브라우저 테스트를 통해 로그인, 정책 검색, 상세 조회, 추천, 챗봇, 알림 등 주요 사용자 흐름을 검증하였다. 운영 환경에서는 health check, 인증, 추천, 북마크, 로그아웃, 관리자 기능, 수집 상태, 알림 상태 등을 smoke test와 운영 관측 스크립트로 확인하였다.

검증 결과 주요 사용자 기능과 관리자 운영 기능이 정상적으로 동작함을 확인하였다. 또한 운영 환경에서도 애플리케이션 health check와 주요 API smoke test가 통과하여, 본 프로젝트가 단순한 로컬 기능 구현을 넘어 실제 배포 환경을 고려한 통합 플랫폼 형태로 구현되었음을 확인하였다.

## 결론 한계점 표현 보정 초안

본 프로젝트는 청년 복지 정책 정보를 통합하고 사용자 조건 기반 맞춤형 추천을 제공하는 플랫폼을 구현하였지만, 공공데이터 기반 서비스와 AI 보조 기능의 특성상 지속적인 개선이 필요한 영역도 존재한다. 첫째, 정책 데이터는 외부 API 제공 상태와 원본 데이터 품질에 영향을 받기 때문에 최신성 및 정확성을 지속적으로 점검해야 한다. 둘째, 추천 품질을 더 높이기 위해서는 실제 사용자의 검색, 조회, 북마크, 알림 반응과 같은 데이터가 충분히 축적되어야 한다. 셋째, AI 추천 사유와 챗봇 답변은 정책 이해를 돕는 보조 정보로 제공되어야 하며, 최종 자격 판단이나 신청 가능 여부는 공식 정책 안내를 통해 확인해야 한다.

향후에는 정책 변경 감지와 데이터 품질 검토 자동화를 고도화하고, 실사용자 반응 데이터를 기반으로 추천 가중치와 알림 기준을 개선할 수 있다. 또한 챗봇 답변의 근거 표시와 신청 준비 코칭 기능을 강화하여 사용자가 정책 탐색에서 실제 신청 준비까지 더 자연스럽게 이어갈 수 있도록 개선할 수 있다.
