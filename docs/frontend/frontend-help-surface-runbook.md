# Frontend Help Surface Runbook

문서군 진입점: [frontend-qa-docs-index.md](./frontend-qa-docs-index.md)

## 목적

이 문서는 공개 도움 경로가 실제 사용자 기준으로 어떻게 이어져야 하는지 정리합니다.

현재 범위는 세 가지입니다.

- `/guide`
- `/support`
- 정책 상세의 `정책 오류 제보`

즉 “서비스를 어떻게 쓰는지”, “서비스를 쓰다가 막혔을 때 어디로 가는지”, “정책 데이터가 틀렸을 때 어디에 제보하는지”를 한 번에 다시 확인하는 runbook 입니다.

## 현재 기준

### 1. `/guide`

- 헤더 `이용가이드`
- 메인 CTA
- 모바일 하단 `가이드`

에서 항상 진입 가능해야 합니다.

`/guide` 에서는 최소 아래가 보여야 합니다.

- `청년복지플랫폼을 가장 빠르게 쓰는 방법`
- 빠른 시작 4단계
- 기능별 카드
- `서비스 문의` CTA

### 2. `/support`

`/support` 는 정책 데이터 오류가 아니라 **서비스 사용 문의**를 받는 공개 페이지입니다.

최소 아래 구분이 보여야 합니다.

- `서비스 사용 문의 / 의견 제안`
- `서비스 사용 문의`
- `정책 오류 제보와는 다릅니다`
- `정책 상세 페이지의 정책 오류 제보` 안내

즉 support는

- 로그인/계정
- 추천/챗봇
- 알림/북마크
- 검색/필터
- 기타 의견/제안

같은 사용 문의를 받는 경로이고, 정책 데이터 자체 오류는 정책 상세의 별도 경로로 보내야 합니다.

### 3. 정책 상세 `정책 오류 제보`

정책 상세에는 `⚑ 정책 오류 제보` 버튼이 보여야 합니다.

이 경로는 다음 유형을 받습니다.

- 지역 정보가 다름
- 신청 기간이 다름
- 자격조건 설명이 다름
- 링크/원문이 열리지 않음
- 중복 정책 같음
- 기타

즉 support와 policy error report는 역할이 겹치면 안 됩니다.

## 점검 순서

1. 홈에서 `이용가이드` 진입
2. `/guide` 에서 `서비스 문의` CTA 진입
3. `/support` 에서 `이용가이드 보기` 로 복귀
4. 정책 상세에서 `⚑ 정책 오류 제보` CTA 확인
5. `/support` 공개 문의가 성공 toast까지 완료되는지 확인
6. 비로그인 정책 상세 `⚑ 정책 오류 제보` 가 `/login` 으로 분기하는지 확인
7. `/support` 안내 문구가 policy error report와 역할을 분리하는지 확인

## 현재 Playwright 기준선

관련 smoke는 아래를 기준으로 봅니다.

- `이용가이드와 서비스 문의는 공개 진입면에서 서로 연결된다`
- `서비스 문의 페이지는 정책 오류 제보와 역할을 구분해 안내한다`
- `서비스 문의 페이지는 공개 문의를 접수하고 성공 안내를 보여준다`
- `비로그인 정책 상세 오류 제보는 로그인으로 분기한다`
- `정책 상세는 요약 정보와 오류 제보 CTA를 보여준다`

실행:

```bash
cd frontend
PLAYWRIGHT_GREP='이용가이드와 서비스 문의는 공개 진입면에서 서로 연결된다|서비스 문의 페이지는 정책 오류 제보와 역할을 구분해 안내한다|서비스 문의 페이지는 공개 문의를 접수하고 성공 안내를 보여준다|비로그인 정책 상세 오류 제보는 로그인으로 분기한다|정책 상세는 요약 정보와 오류 제보 CTA를 보여준다' npm run test:e2e
```

## 해석 기준

- `/guide` 진입점이 사라지면 도움 경로 접근성 회귀로 봅니다.
- `/support` 가 policy error report와 역할을 분리하지 못하면 UX 회귀로 봅니다.
- 정책 상세 `오류 제보` CTA가 없으면 정책 데이터 품질 신고 경로 회귀로 봅니다.
