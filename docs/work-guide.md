# 작업 가이드

## 작업 시작

[문서 시작점](README.md), [현재 상태](current-state.md), 작업 분야의 목차에서 필요한 부분을 확인합니다. 모든 설계 이력과 운영 체크리스트를 매번 읽지는 않습니다.

명령을 실행할 때는 [환경 안내](core/environment-guide.md)를 기준으로 실행 위치·앱·DB·영향을 확인합니다. `local` 파일명, `prod` 프로필, `127.0.0.1`만으로 대상을 결정하지 않습니다.

## 작업 원칙

- 요청한 목표·제외 범위·완료 조건을 정하고 관련 변경만 수행합니다.
- 현재 동작은 코드와 재현으로, 기대 동작은 요구사항과 승인된 결정으로 확인합니다. 둘의 불일치는 정상 동작처럼 문서화하지 않습니다.
- 로컬·서버·합성 표본·실사용자 관측을 분리합니다. 없는 환경과 실행하지 않은 검사를 있다고 가정하지 않습니다.
- 운영 변경·데이터 삭제·외부 발송은 문서 정리나 일반 코드 검증에 포함하지 않습니다.
- 테스트와 문서의 보안·데이터 보존 계약을 단순화를 이유로 제거하지 않습니다.
- Git 작업은 [github-workflow.md](github-workflow.md)를 따릅니다. 푸시는 요청이 있을 때만 합니다.

## 완료와 기록

1. 영향 범위의 테스트와 문서 참조를 확인합니다.
2. 실제 실행한 명령·결과·미확인 범위를 [phase-plan.md](phase-plan.md)에 기록합니다.
3. 재발 가능성이 있거나 판단 근거를 남길 필요가 있는 문제만 [troubleshooting-log.md](core/troubleshooting-log.md)에 기록합니다.
4. 현재 구현이 바뀌면 해당 현재 상태·계약 문서만 갱신합니다. 같은 설명을 여러 목차에 복사하지 않습니다.

## 문서 정리

- 로컬용과 서버용의 설정·권한·안전 절차 차이는 중복으로 제거하지 않습니다.
- 현재 계약, 실행 절차, 작성 템플릿, 관측 이력은 역할이 다르면 분리할 수 있습니다.
- 합치거나 보관하기 전에 원본의 유효한 정보가 이동할 문서·절과 관련 코드/테스트 참조를 확인합니다.
- 과거 기록은 날짜·환경·의미를 바꾸지 않고 보존합니다. 이동 시 상대 링크와 내부 앵커를 확인합니다.
- 새 문서보다 기존 문서의 적절한 절을 우선합니다. 문서별 대표 위치는 [documentation-map.md](documentation-map.md)를 확인합니다.
